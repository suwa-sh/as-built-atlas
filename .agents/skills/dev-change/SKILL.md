# このリポジトリを直すときの流れ

守ることの正本は `docs/rules/` にある。ここには、進め方だけを書く。

```text
1 触る部分を決める → 2 ルールを読む → 3 直す → 4 テスト → 5 実物で確かめる
→ 6 文書を直す → 7 外部レビュー → 8 知識を残す → 9 報告
```

## 1. 触る部分を決める

頼まれたことを、次の部分に当てはめる。2 つ以上にまたがることが多い。

| 部分 | 場所 |
|---|---|
| 形式と語彙 | `schema/` |
| ツール | `abatlas/*.py` |
| 集計表と宣言 | `dbt-template/`、`profiles/*/dbt-template/`、`abatlas/declarations.py` |
| 画面 | `abatlas/webapp/` |
| プロファイル | `profiles/` |
| 見本 | `examples/` |
| 文書 | `README.md`、`docs/` |

頼まれたことを部分に当てはめたら、足りない観点が無いかを考える。人に確かめるかどうかは、`docs/rules/common.md` の「進め方」で決める。

## 2. ルールを読む

- `docs/rules/common.md` は、いつも読む。
- `docs/rules/README.md` の表で、触る部分のルールを選んで読む。
- 上流 (形式、プロファイル) を変えるときは、下流 (ツール、集計表、画面、見本) のルールも読む。
- `.agents/memory/index.md` から、関係するはまり所を読む。

## 3. 直す

手順 2 で読んだルール (`docs/rules/common.md` の「進め方」と、触る部分のルール) に従って直す。直す前に、同じことをする部品や決まりが既に無いかを探す。

部分ごとの手順は、次の skill にある。

| 場面 | skill |
|---|---|
| 表示の種類か、メニューの項目を足す | `dev-add-view` |
| 見本に関わる変更 (形式、プロファイル、抽出器、生成スクリプト、画面の見た目) | `dev-sample-regen` |

## 4. テスト

```bash
uv run pytest -q
```

- 新しい動きには、テストを足す。止まる条件 (エラーにする場合) は、条件ごとに確かめる。
- main へ push するか、pull request を作ると、GitHub Actions が同じテストを流す。push した後は、結果を見る (`gh run list --limit 1`)。
- 画面の動きは、テストでは見ていない。次の手順で確かめる。

## 5. 実物で確かめる

テストが通っても、ここを飛ばさない。

| 変えた部分 | 確かめ方 |
|---|---|
| 画面 | skill `dev-webapp-verify` |
| 形式、ツール、集計表 | 見本の分析リポジトリで、検査と集計をやり直す (コマンドは、skill `dev-webapp-verify` の `references/sample-repos.md` の「検査と集計をやり直す」) |
| プロファイル | 同上。先に、見本の中の配布物のコピーを置き換える。入口の拾い方や包む関係を変えたときは、列挙もやり直す (同じ資料の「プロファイルを変えたとき」) |
| 配布物の中身 | イメージを作り直し、分析リポジトリで `upgrade .` を試す |

## 6. 文書を直す

- 変えた事実を、`README.md` と `docs/` で探して直す。
- 決定を変えたかを考える。変えたなら、`docs/rules/common.md` の「知識を残す」に従う (書き方は skill `dev-docs`)。
- 文書を直したら、skill `dev-docs` で確かめる。

## 7. 外部レビュー

`docs/rules/common.md` の「レビュー」に従う。直したら、手順 4 と 5 (テストと実物の確認) をやり直してから、もう一度見てもらう。

## 8. 知識を残す

1. 今回の作業でわかったこと (学び)、リファクタの案、残っている作業 (前の報告から持ち越したものを含む) を、書き出す。それぞれに、1 から番号を振る。
2. 学びごとに、`docs/rules/common.md` の「知識を残す」の図で、置き場を選んで書く。
3. `.agents/memory/` に書いたら、`.agents/memory/index.md` に 1 行足す。

## 9. 報告

次を、分けて書く。

| 項目 | 内容 |
|---|---|
| 変えたこと | 何を、なぜ |
| 確かめたこと | テスト、実物の操作、目で見た画面 |
| 確かめていないこと | 見ていない画面、試していない場合 |
| 判断したこと | 頼まれていないが決めたことと、理由 |
| 学び | 番号、今回わかったこと、どこに書いたか |
| リファクタの案 | 番号、案、効くところ、手間 |
| 残っている作業 | 番号、作業、いまの状態、進めるのに要ること |

学び、リファクタの案、残っている作業の番号の振り方は、`docs/rules/common.md` の「学び・リファクタの案・残っている作業の書き方」に従う。

コミットと push の扱いは、`docs/rules/common.md` の「進め方」に従う。
