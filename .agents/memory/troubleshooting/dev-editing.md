# 直すときの、はまり所 (このリポジトリの開発)

## 画面のコードに文字を書いたら、呼び名の検査が落ちる

- 適用対象: abatlas/webapp/ の、画面に出る文字
- 症状: tests/test_terms.py が落ちる
- 原因: 画面は、呼び名を直接書かない決まり。用語集にある呼び名 (mart、entry point など) を文字で書くと落ちる
- 検出: uv run pytest -q tests/test_terms.py
- 復旧: `term("<id>")` で引く。用語集に無い概念なら、schema/vocab/terms.yaml に足す
- 再発防止: 画面に出す文を書くときは、名詞が用語集にあるかを先に見る
- 最終確認日: 2026-11-15

## 作業定義だけに足したつもりの項目が、見本の分析結果すべてに写る

- 適用対象: examples/generator/kotori_books.py と、共有している形式の定義
- 症状: 生成し直すと、分析結果 34 件と入口の一覧まで変わる
- 原因: 生成スクリプトが、対象の情報 (target) を、作業定義・入口の一覧・分析結果で使い回している。形式の定義も、3 つが同じ定義を参照している
- 検出: 生成し直した後に、git status --short examples を見る
- 復旧: 生成スクリプトで、作業定義だけに足す
- 再発防止: 生成し直したら、変わったファイルの範囲を必ず見る
- 最終確認日: 2026-11-15

## プロファイルの自由文に、呼び名の置き換えを足すと壊れる

- 適用対象: profiles/*/profile.yaml の layers[].invokes_next
- 症状: コードの例の波かっこが、呼び名の参照として扱われる
- 原因: invokes_next は、コードの例を書く自由文 (例: 波かっこを含む URL の文字列)
- 検出: プロファイルの中の波かっこを探す
- 復旧: 置き換えの対象にしない。対象は、label、layers の label と tier、hierarchy.notes の text だけ
- 再発防止: 置き換えの対象を増やす前に、既にあるプロファイルの文を読む
- 最終確認日: 2026-11-15

## 分析リポジトリの中のプロファイルのコピーには、集計の定義が無い

- 適用対象: abatlas/build.py、abatlas/layout.py
- 症状: プロファイルの置き場所だけから集計の定義を読もうとすると、プロファイル固有の集計表が消える
- 原因: init と upgrade は、プロファイルを写すときに dbt-template/ を除く
- 検出: 分析リポジトリの `.abatlas/profiles/<id>/` の中身を見る
- 復旧: 置き場所に dbt-template/ があればそれ、無ければ配布物のものを使う
- 再発防止: 配布物のコピーに何が入るかは、abatlas/layout.py の写し方で確かめる
- 最終確認日: 2026-11-15

## mermaid の図が、文字どおりに描かれない

- 適用対象: 文書の図
- 症状: 箱が別の形になる、または描けない
- 原因: 箱の文字の [/…/] や [(…)] は、形の記法。山かっこは、タグとして扱われることがある
- 検出: uv run --locked python .agents/skills/dev-docs/scripts/check_docs.py
- 復旧: かっこ・スラッシュ・波かっこ・山かっこを含む文字は、引用符で包む
- 再発防止: 図は、書いたら必ず描く
- 最終確認日: 2026-11-15

## 分析リポジトリに配る文書から、配られないファイルへのリンクが切れる

- 適用対象: docs/architecture/、docs/guide/、docs/reference/
- 症状: 分析リポジトリの .abatlas/docs/ の下の文書から、リンクを辿れない
- 原因: 分析リポジトリに配るのは docs/architecture/、docs/guide/、docs/reference/ だけ (DESIGN.md、ルートの README.ja.md、docs/rules/、docs/adr/ は配らない)
- 検出: uv run --locked python .agents/skills/dev-docs/scripts/check_docs.py
- 復旧: リンクにせず、文で指す。配る置き場どうしは、リンクでよい
- 再発防止: 配る置き場から外を指すときは、配られるかを考える。配る置き場を増やすときは、abatlas/layout.py、Dockerfile、check_docs.py の SHIPPED を合わせて直す
- 最終確認日: 2026-11-23

## ast-grep が、通常の例外でなく異常終了で失敗を返す

- 適用対象: abatlas/extractors/ast_query.py (構文を読む抽出器、code-search)
- 症状: 読めない言語や、規則の誤りを渡すと、標準エラーに panic の文が出て、except Exception を素通りする
- 原因: ast-grep-py は、失敗を PanicException (BaseException の子) で返すことがある
- 検出: uv run pytest -q tests/test_ast_query.py (止まるときの文を、条件ごとに確かめている)
- 復旧: 言語名は、呼ぶ前に SUPPORTED_LANGUAGES で確かめる。規則の誤りは BaseException で受けて、理由を付けた SystemExit に変える (KeyboardInterrupt と SystemExit は、そのまま通す)
- 再発防止: ast-grep-py の版を上げたら、読める言語の一覧 (定数) と、止まるときのテストを流し直す。版は固定してある (pyproject.toml)
- 最終確認日: 2026-11-16

## 項目名を機械的に置き換えると、説明の文と、用語の id が巻き込まれる

- 適用対象: 項目名の入れ替え (複数のファイルにまたがる置き換え)
- 症状: 説明の文で語の意味が入れ替わる (例: 「zone は枠 (画面での呼び名は tier)」が、順に置き換わって崩れる)。用語の id やテストの検査対象の語まで置き換わり、検査が弱くなる
- 原因: 同じ語が、項目名・用語の id・説明の文の 3 つで使われている。置き換えは、意味を見ない
- 検出: 置き換えの前の差分から、両方の語を含んでいた行を抜き出して読む。置き換えの後に、同じ語が重なった並び (例: "layer", "layer") を探す
- 復旧: 崩れた行を、手で直す
- 再発防止: 置き換える前に、その語を含む語 (timezone、external_zone など) と、用語の id としての使われ方を洗い出す。置き換えの順番を決める (意味が移る語は、移り先を先に空ける)。見本は、変換の前後を YAML として読み比べる
- 最終確認日: 2026-11-15

## プロファイルの説明に決まりを足したら、同じ文書の別の節と食い違う

- 適用対象: `profiles/<id>/context.md` に、語の一覧や決まりを足すとき
- 症状: 足した一覧と、層の節に前からある一覧 (「フレームの `kind` は、次の語から選ぶ」) が食い違う。分析するエージェントが、読んだ節によって違う語を選ぶ
- 原因: 決まりを書く場所が、プロファイルごとに違う (層の節、「フレームにするもの・しないもの」の節、表の中)。引き継ぎのメモの「いまは 2 つだけ」を確かめずに進めた
- 検出: `grep -n "語から選ぶ" profiles/*/context.md` と、`kind` を含む行の grep で、前からある決まりを全部のプロファイルで探す
- 復旧: 前からある一覧を正にして、足した文を戻すか、前からある一覧の行に補足する
- 再発防止: 決まりを足す前に、同じ文書の全文と、ほかのプロファイルの同じ決まりを grep で洗い出す。足すのは、本当に無いプロファイルだけ
- 最終確認日: 2026-11-24
