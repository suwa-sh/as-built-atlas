# リポジトリのメモリー

エージェント専用 knowledge の入口です。短い routing table として保ち、詳細は各ファイルに置きます。

## 基本の期待状態

- リポジトリ全体を変更するとき: [リポジトリの期待状態](../../docs/architecture/README.md)
- 作業を完了する前: [品質ゲート](../../docs/rules/common.md)
- このリポジトリを直すとき: skill `dev-change` (触る部分ごとのルールは [rules の地図](../../docs/rules/README.md))
- 決定の経緯を知りたいとき: [ADR](../../docs/adr/README.md)

## 必要なときに読む

- CI が失敗したとき: [CI のトラブルシューティング](../../docs/troubleshooting/README.md)
- 直しても画面が変わらない、テストは通るのに壊れている、イメージやコミットフックの検証に迷う、CI と手元の複雑度が異なるとき: [確かめるときの、はまり所](troubleshooting/dev-verify.md)
- 呼び名の検査が落ちる、見本の差分が広がる、図が描けない、配布先でリンクが切れる、構文を読む抽出器が異常終了するとき: [直すときの、はまり所](troubleshooting/dev-editing.md)

## 書くもの、書かないもの

- ここは、エージェントだけが読む。人も守る決まりは `docs/rules/` に、決定の経緯は `docs/adr/` に書く
- 作業中に得た、今後の作業でも理解しておくべきこと (はまり所、確かめ方のこつ、道具の癖) を書く
- 手元の環境だけの値 (絶対パス、ポート、個人の情報) は書かない

## 昇格ルール

- 一つのスキルだけで使う知識は、そのスキルの `references/` に置く
- 二つ以上のスキルで再発したら、`desired-state/` または `troubleshooting/` へ昇格し、この索引に 1 行足す
- 製品の自動生成メモリーの内容は、再現確認してから明示ファイルへ移す
