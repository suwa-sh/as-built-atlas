# 0035. 文書を読み手の目的で分け、使う人の手引きを配る

- 状態: 採用
- 記録した日: 2026-11-23

## 背景

仕組みの説明は、部品ごとの文書に分かれていた ([0007](0007-docs-by-topic.md))。
使う人の手順は、ルートの README と、仕組みの説明の 4 つの文書と、skill の本文に散らばっていた。
1 つの文書に、手順、仕様、開発者だけが要る内容が混ざり、プロファイルの文書は 463 行になっていた。

使う立場で読むと、人が何をすれば何が手に入るのか、その途中でどの skill とコマンドが動くのかを、1 か所で追えなかった。

## 決定

- 文書の置き場を、読み手の問いで分ける。

  | 置き場 | 読み手の問い |
  |---|---|
  | `docs/guide/` (手引き) | どうやるか |
  | `docs/architecture/` (仕組みの説明) | なぜこうなっているか |
  | `docs/reference/` (仕様) | 正確には何か |
  | `docs/rules/` (開発の決まり) | 直すとき何を守るか |
  | `docs/adr/` (決定の経緯) | なぜそう決めたか |

- 手引きの入口に、段階ごとの「人がやること、裏で動くもの、手に入るもの」の表を置く。
- 手引きと仕様は、仕組みの説明と同じく、分析リポジトリに配る。
- ルートの `README.md` は、分析リポジトリに配るのをやめる。リポジトリの紹介であり、画像、見本、変更の記録へのリンクが配布先で切れる。分析リポジトリでの入口は、手引きの入口とする。
- 仕組みの説明の入口 (`docs/architecture/README.md`) は、場所と名前を変えない。
- 移す順は、手引き、仕様、仕組みの説明の短縮とする。区切りごとに、参照を直す。

0007 の決定のうち、見た目の正本を 1 つにすること、表とリストと図で書くこと、日本語の呼び名で書くことは、そのまま守る。

## 捨てた案

| 案 | 捨てた理由 |
|---|---|
| いまの置き場のまま、長い文書を分ける | 長さは減るが、手順と仕様の混在が残る。使う人の入口ができない |
| 文書の入口の表だけを、読み手別に直す | 辿りやすくはなるが、辿った先の文書が、使う人の言葉で書かれていない |
| 古い場所に、転送用のファイルを残す | 同じ事実を 2 か所に書かない決まりに反する。リンク切れはテストが止める |

## 結果

- 配る置き場が増えるので、配布の一覧 (`abatlas/layout.py`)、イメージ、リンクの検査を合わせて直す。検査は、配る置き場どうしのリンクを許し、その外へのリンクを止める。
- 文書の書き方と置き場の決まり: [../rules/docs.md](../rules/docs.md)。
