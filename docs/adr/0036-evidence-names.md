# 0036. 根拠の近くに名前が無い主張を、合否を付けずに並べる

- 状態: 採用
- 記録した日: 2026-11-23

## 背景

分析結果の機械チェックは、根拠のファイルがあるかと、行番号が行数を超えないかだけを見ていた。
行がずれた根拠や、関係のない場所を指す根拠は、行があれば通り、レビューするエージェントが読むまで見つからなかった。
公開している見本のレビューでは、指摘の 3 割が「根拠が主張を支えていない」だった。

コードから機械で作ったものと分析結果を突き合わせる検査を、reverse-spec-flow のコードグラフを手掛かりに検討した。
あのコードグラフは、エージェントが表に書くもので、呼び出しの線は機械では検査されていなかった。
取り入れたのは、検査の側が自分でコードを読んで突き合わせる、という考え方である。[コードグラフのひな形](https://github.com/aws-samples/sample-reverse-spec-flow/blob/caa0a9d147b79d7bb4432552554611c24afe8be1/templates/code-graph.md.template)

## 決定

- 根拠の行の前後 5 行に、主張が名指しするものの名前が出てくるかを見るコマンド (`evidence`) を足す。
- 見る主張は、呼び出し (呼び先のファイル名と、名前の中の語)、読み書きの相手 (いちばん下の段の値の語)、設定 (名前) の 3 つ。語のどれか 1 つが、語の区切りで一致すればよい。
- 合否は付けない。見つからなかった主張を並べるだけにする。
- 並んだ主張は、分析する側が根拠を直すか、理由を説明する (結果の `notes` に書く)。レビューする側は、同じ一覧を出して、並んだ主張から確かめる。

## 捨てた案

| 案 | 捨てた理由 |
|---|---|
| 見つからなければ、機械チェックを不合格にする | 正しい主張でも、名前が近くに無いことがある (接続先の設定から来るデータベースの名前、実行時に組み立てる名前)。不合格にすると、そこで分析が止まる |
| 呼び先は、名前の先頭の語だけを探す | 見本 (画面を持つシステム、呼び出し 5,160 件) で、正しい主張を 6% 並べた。行をずらした根拠に気付く割合は、4 ポイントしか上がらなかった |
| 列の名前も見る | 同じ見本で、正しい主張の 21% を並べた。列の名前は、呼び出し元や型の定義にあることが多い |
| テーブルや設定の名前をコードから全部拾い、すべての分析結果と突き合わせる | 書き漏れも分かるが、拾い方の設定と集計表が要る。先に、手間の小さいこの決定の効き目を見る |
| 機械で作った呼び出しのグラフと、処理の段の連なりを突き合わせる | import の解決が言語ごとに違う。設定や定義ファイルでつながる呼び出しは、構文に出ない。レビューの指摘のうち、辿り漏れは 1 割に満たない |
| エージェントが、分析の前にノードとエッジの表を書く | 書くのがエージェントなので、機械の検査にならない。分析結果と二重に保守することになる ([0034](0034-code-map.md) でも退けた) |

## 結果

- 見本 2 つで、いまの検査を素通りする「20 行のずれ」に気付いた割合は、設定で 99%、呼び出しと読み書きの相手で 5 割前後だった。正しい主張を並べた数は、設定で 1,080 件中 1 件、呼び出しで 5,160 件中 0 件だった。
- 名前が近くにあっても、主張を支えているとは限らない。ずれた先にも同じ名前がある根拠と、書き漏れ、辿り漏れは、この一覧には出ない。レビューは、並ばなかった主張も確かめる。
- 探す語には、`src` のような一般の語も入る。並べる数を抑えるために緩くしてあり、合否に使うには粗い。
