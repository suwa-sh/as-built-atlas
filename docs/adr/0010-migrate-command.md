# 0010. 項目名の入れ替えは、変換のコマンド (migrate) で移せるようにする

- 状態: 採用
- 記録した日: 2026-11-16

## 背景

項目名を入れ替えたとき ([0009](0009-field-names-match-labels.md))、既にあるファイルは、一時的なスクリプトで書き換えた。スクリプトは配布物に入れなかったので、手元に前の項目名の分析リポジトリがある人は、手で書き換えるしかなかった。

公開の後に形式を変えると、利用者の分析リポジトリに、前の形式のファイルが残る。分析し直すのは費用がかかり、結果も変わる。機械的に移せる変更は、利用者が自分で移せる必要がある。

## 決定

- 配布物に、変換のコマンド `abatlas migrate <分析リポジトリ>` を入れる。
- 判断を変えずに、機械的に移せる形式の変更 (項目名の入れ替えなど) をするときは、同じ変更で、このコマンドに変換を足す。

| 決めたこと | 内容 |
|---|---|
| 書き換える対象 | 分析する側が持つもの: 入口の一覧、分析結果、独自の集計表の宣言、自分用のプロファイル |
| 書き換えない対象 | 配布物のコピー (`.abatlas/`。`upgrade` が置き換える) と、分析リポジトリの外。リンクを辿った先で判定する |
| 変えるもの | 項目の名前だけ。値と書式 (コメント、並び、引用符) は変えない。例外は 1 つ: 文 (値) の中で項目を指している「`(tier: <id>)`」は、「`(layer: <id>)`」に直す ([0009](0009-field-names-match-labels.md) の「結果」と同じ) |
| 確かめ方 | 読み込んだ YAML の上で「項目名だけを入れ替えた姿」を作り、文字を置き換えた結果を読み直して突き合わせる。合わなければ、そのファイルは書き換えずに知らせる (文の中に項目と同じ形の行がある、アンカーなどで置き換えられない、前の名前といまの名前が並んでいる、コメントも変わる) |
| 書き込み | 同じ場所の一時ファイルに書いてから、入れ替える (途中で止まっても、元のファイルが半端にならない) |
| 繰り返し | 2 回動かしても、2 回目は何も変えない |
| SQL | 書き換えない。前の名前らしい語があるファイルを知らせる (列の名前か、ほかの語かを、機械では決められない) |

## 捨てた案

| 案 | 捨てた理由 |
|---|---|
| 検査 (`validate`) や集計 (`build`) の中で、前の項目名を読み替える | 前の形式のファイルが、いつまでも残る。読み替えの分岐が、検査・ETL・画面に広がる |
| `upgrade` の中で、自動で書き換える | `upgrade` が触るのは、OSS が持つパスだけ、という境が崩れる。利用者のファイルを、頼まれずに書き換えることになる |
| YAML を読み込んで、書き出し直す | コメントと並びが失われ、差分が広がる |

## 結果

- [0009](0009-field-names-match-labels.md) の「結果」にある、手で書き換える手順は、このコマンドに置き換わった。
