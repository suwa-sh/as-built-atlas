# 0006. ツールが読むプロファイルは、作業定義の profile.dir の 1 か所にする

- 状態: 採用
- 記録した日: 2026-11-15

## 背景

作業定義には、プロファイルの置き場所を書く項目 (`profile.dir`) があったが、読むコードが無かった。
検査と列挙は、分析リポジトリの中のコピーを `--profile` で受け取り、集計だけが配布物の中のプロファイルを読んでいた。

- 配布物を新しくして、コピーの更新を忘れると、検査と集計が別の版で動く。
- 利用者が、自分のシステムに合わせて層を減らす・足す手段が無い。

## 決定

- 集計も、作業定義の `profile.dir` のプロファイルを読む。未記入なら、配布物の `profiles/<id>`。
- 場所に `profile.yaml` が無い、分析リポジトリの外を指す、空の文字、`id` が違う、検査に通らないときは、**配布物へ黙って切り替えずに止まる**。
- プロファイル固有の集計表は、その場所に `dbt-template/` があればそれ、無ければ配布物のものを使う。
- 自分用に直すときは、更新で置き換わらない場所 (`analysis/profiles/<id>`) に写す。

## 捨てた案

| 案 | 捨てた理由 |
|---|---|
| 項目を消して、すべてのコマンドが配布物だけを読む | 食い違いは消えるが、利用者がプロファイルを調整できない |
| 置き場所に無ければ、配布物に切り替える | 書き間違いに気づけず、別のプロファイルで集計が進む |

## 結果

- 残る課題: 配布物のコピーと配布物の版が違うとき、集計は警告しない。
- 残る課題: `profile.dir` の中の `dbt-template/` が外を指すリンクでも読む (分析リポジトリの持ち主は、もともと独自の集計の定義を置ける。安全の境界ではない)。
- 最新の状態: [../architecture/profiles.md](../architecture/profiles.md) の「ツールが読むプロファイル」。
