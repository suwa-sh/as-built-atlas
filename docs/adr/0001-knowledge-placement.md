# 0001. 知識の置き場を 3 つに分ける (ADR / docs / agent memory)

- 状態: 採用
- 記録した日: 2026-11-15

## 背景

開発の決まりと経緯が、仕組みの説明、見た目の文書、テスト、会話の中に散らばっていた。
同じことが 2 か所に書かれ、片方だけが古くなることがあった。

## 決定

知識を、読み手と役割で 3 つに分ける。

| 置き場 | 書くこと | 読み手 |
|---|---|---|
| `docs/adr/` | 決定の経緯 (背景、決定、捨てた案、結果) | 人とエージェント |
| `docs/` の ADR 以外 | 守るべき最新の状態。経緯は書かず、ADR を指す | 人とエージェント |
| `.agents/memory/` | 作業中に得た、今後の作業でも理解しておくべきこと (はまり所、確かめ方のこつ) | エージェントだけ |

- 決定を変えるときは、新しい ADR を足して、古い ADR の状態を「置き換え済み」にする。`docs/` は最新の状態に書き換える。
- `docs/` から `.agents/memory/` は参照しない (一方向)。
- 作業が終わったら、学びとリファクタの案を挙げる。学びのうち、今後も効くものを agent memory に、決まりにするものを `docs/rules/` に書く。

## 捨てた案

| 案 | 捨てた理由 |
|---|---|
| 経緯も最新の状態も `docs/` の同じ文書に書く | 文書が長くなり、いま守ることが読み取りにくい |
| 学びをすべて `docs/` に書く | 人が読む文書に、エージェントの作業のこつが混ざる |

## 結果

- `docs/rules/` に部分ごとのルール、`.agents/skills/dev-*` に開発の手順を置く。
- ADR は、決定のたびに 1 ファイル足す。
