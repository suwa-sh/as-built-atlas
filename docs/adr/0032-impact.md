# 0032. 対象 Git の差分を入口ごとの作業一覧に変換する

- 状態: 採用
- 記録した日: 2026-11-22

## 背景

対象コミットを進めると、従来はすべての入口が再分析対象になった。共有する処理の変更は複数の入口に届く。前回の各結果には、その処理と主張の根拠がすでに残っている。

## 決定

対象を固定した版で全件列挙し、前回の入口一覧と比較する。各結果が実際に分析した版から今回までの Git 差分と、その結果の定義場所・根拠を照合する。人が未記録の影響を確認した入口については、元結果と有効な版を結ぶ別の確認記録を残す。

| 検討した案 | 判断の理由 |
|---|---|
| 根拠行に重なる差分だけを見る | 条件分岐の追加や引用行の移動を拾うため、ファイル単位で判定する |
| 前回の確認済みの版から連鎖させる | 実際に読んだ版と照合すると、途中の確認記録に依存しない |
| 分析結果のコミットを一括更新する | 分析した版と再利用を確認した版には別の意味がある |

## 結果

共有処理の変更理由をまとめ、入口ごとに呼び出し経路を示せる。分析担当者は共通部分を一度読み、各入口の文脈で影響を確かめる。仕組みと手順は[対象コードの差分](../reference/update-commands.md)にある。
