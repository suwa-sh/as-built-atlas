# 0015: 届かないように見える呼び出しの書き方を、届かない理由で 1 つに決める

- 日付: 2026-11-19
- 状態: 採用

## 背景

コードには書いてあるが、その入口からは実際には通らない分かれ道がある。分析の決まりは、2 つの場合だけを書いていた。

| 場合 | 決まり |
|---|---|
| 入口の木の中のコードが直接書いた固定の値で、決して成り立たない | 辿らない |
| それ以外で、成り立たないように見える | 消さずに `conditional` で書き、理由を書く |

umami の 67 件を分析し直したとき、この 2 つに当てはまらない場合で、入口ごとに書き方が割れた。分析したエージェントが報告した迷いは 59 件あり、その多くがこの論点だった。

| 割れた場合 | 起きた書き方 |
|---|---|
| 受け口の検証が、その値を誤りとして弾くので、先の分かれ道に決して着かない | フレームにしない / `conditional` で残す |
| 値が、画面のパスや状態で決まり、実際には 1 つに決まっていそう | `conditional` で残す (ここは割れなかったが、決まりに無かった) |
| 同じ関数に、閉じた経路と、開いた経路の両方から着く | 開いた側の下に、もう一度書く / 開いた側の下へ移す / `conditional` のフレーム 1 つにまとめる |
| 部品を別の入口に分けたとき、描く側が渡さない値で、部品の中の枝が閉じる | 描く側の概要に書く / 書かない |

## 決めたこと

| 決めたこと | 中身 |
|---|---|
| 書き方は、届かない理由で決める | 上から順に当てはめる表を、分析の skill に置く。1: 固定の値で閉じている → 辿らない。2: 手前のコードが、条件が成り立つ値をすべて弾く → 辿らない。3: 入口の外から来る値で決まる → `conditional` と理由 |
| 「手前のコードが弾く」は、3 つを確かめたときだけ | 弾く行と条件の行が、どちらも入口の木の中にあり、迂回する経路が無い / 弾く範囲がコードから読み切れる / 成り立つ値がすべて弾かれる |
| パスや状態で決まる値は、閉じた扱いにしない | 実際には 1 つに決まっていそうでも、コードに直接書いた値ではない |
| 当てはめる単位は、経路 | 同じ処理に、複数の呼び出し元から着くときは、呼び出し元ごとに、閉じているかを決める |
| 呼び出し元によって閉じたり開いたりするときは、開いている呼び出し元の下に、もう一度書く | 閉じている経路の下には書かない。移さない。1 つにまとめない。プロファイルの「もう一度書くのは、終端になるときだけ」の、もう 1 つの例外 |
| 分けた部品の中の分かれ道は、描く側に書かない | 部品の結果では、描く側が渡す値は、入口の外から来る値 |

## 考えた案

| 案 | 採らなかった理由 |
|---|---|
| 入口のパスで決まる値も、閉じた扱いにする | 入口のパスは、動く段 (`[id]`) や、同じ部品を描く別の画面で変わる。どこまでが固定かの判断が、分析者によって割れる |
| 呼び出し元によって閉じたり開いたりするときは、`conditional` のフレーム 1 つにまとめる | 木が小さくなるが、「どの経路から届くか」が消える。閉じた経路の下に、届かない読み書きが出る |
| 開いた側の下へ、フレームを移す | 「同じ処理は、最初に着いた呼び出し元の下に書く」と食い違い、分析者が違うと木が変わる |
| 届かないように見える呼び出しは、すべて辿らない | 状態や保存されたデータで決まる呼び出しは、別の条件で動く。消すと、読み書きの漏れになる |

## 影響

- 分析の skill の版は、3 つ目の数字だけを上げる。前の版の結果は、弾かれる枝を `conditional` で余分に持つか、開いている枝の置き場が違うだけなので、再分析の対象にしない。
- もう一度書いたフレームの読み書きは、集計が 2 回数えない ([0014](0014-shared-parts-as-entries.md) の `is_repeat`)。この仕組みがあるので、「もう一度書く」を選べた。
- レビューの skill は、弾かれる枝がフレームに無くても、漏れに数えない。前の版の結果の書き方は、指摘しない。
- umami の見本は、前の決まりで書いた結果のままで、入口によって書き方が割れている所が残る。
