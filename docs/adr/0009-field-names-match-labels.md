# 0009. 設定と分析結果の項目名を、画面の呼び名にそろえる

- 状態: 採用
- 記録した日: 2026-11-15

## 背景

画面の呼び名は、用語集で英語の技術用語にそろえた ([0002](0002-labels-from-glossary.md)): 処理が属する段は layer、layer をまとめる区分は tier。
しかし、設定と分析結果の項目名は、前の名前のままだった。`tier` という語が、3 つの意味で使われていた。

| 前の項目名 | 値 | 意味 | 使われていた場所 |
|---|---|---|---|
| `tiers` | 層の定義の並び | 層の並び | プロファイル |
| `tier` | 層の id | その処理・入口が属する層 | 分析結果、入口の一覧、抽出器の出力と引数、プロファイルの抽出器と「包む関係」、集計表の列 |
| `zone` | 区分の名前 | 層をまとめる区分 | プロファイル |
| `tier` | core / profile / repo | 集計表の持ち主 | 集計表の宣言 |

画面で「tier」と見た人が設定を探すと、別の意味の `tier` に当たる。公開の前なので、いま直せる。

## 決定

| 意味 | 新しい項目名 |
|---|---|
| 層の並び | `layers` |
| 層の id を持つ項目 | `layer` (抽出器の引数は `--layer`、集計表の列も `layer`) |
| 層をまとめる区分 | `tier` (`layers[].tier`) |
| 集計表の持ち主 | `origin` |

- 文書と、エージェント向けの文 (skill、プロファイルの `context.md`) の「ティア」は、「層」に直す。
- 形式の版 (`format_version`) は上げない。公開の前で、古い形式のファイルを持つ利用者がいないため。古い項目名のファイルは、形式の検査が「`layer` が無い」と指摘する。
- 分析 skill の版と、プロファイルの版は上げない。判断の規則は変わらず、既にある結果は、機械的な変換で移せる。版を上げると、変換した結果がすべて再分析の対象になる。
- 既にある見本は、変換して移す。ことり書店は、生成し直す。umami は、項目名だけを、書式を保ったまま書き換える (変換の前後を YAML として読み比べ、項目名のほかが変わっていないことを確かめる)。

## 捨てた案

| 案 | 捨てた理由 |
|---|---|
| プロファイルの項目名だけを変える (`tiers` → `layers`、`zone` → `tier`) | 分析結果の `tier` は層、プロファイルの `tier` は区分になり、同じ名前が逆の意味を持つ |
| 変えない。言葉の表で、対応を説明する | 説明が要る状態が、公開の後も残る。公開の後に変えるのは難しい |
| umami の見本を、分析し直す | 費用がかかり、結果も変わる。項目名の変更は、内容を変えない |

## 結果

- 文の中で項目を指していた「(tier: layout)」という書き方 (umami の分析結果の `notes`) も、「(layer: layout)」に直した。ほかの文は変えていない。
- 画面の図の部品の中で、枠を指す内部の名前 (`zone`) は、そのまま残した (図の部品の名前で、設定の項目ではない)。
- 過去の記録 (これより前の ADR) は、前の項目名のまま。
- 手元に、前の項目名の分析リポジトリがあるときは、入口の一覧と分析結果の `tier` を `layer` に、独自の集計表の宣言の `tier` を `origin` に書き換える。
- 最新の状態: [../architecture/README.md](../architecture/README.md) の「言葉」、[../rules/schema.md](../rules/schema.md) の「項目名」。
