# 0002. 画面に出す呼び名は用語集で決める

- 状態: 採用
- 記録した日: 2026-11-15

## 背景

画面の呼び名が、画面のコード・集計表の宣言・プロファイルに直接書かれていた。
同じ概念が場所によって違う名前で呼ばれ、日本語の言い換え (例: 入口、処理) が、保守するエンジニアの普段の言葉と合っていなかった。

## 決定

- 概念 1 つに呼び名 1 つ。正本は `schema/vocab/terms.yaml`。
- 技術用語は英語のまま出す (例: entry point、function、datastore)。
- 宣言・プロファイルの表示項目・語彙には `"{id}"` と書き、build が配る前に呼び名へ置き換える。
- 画面は `/meta` の `terms` を `term("<id>")` で引く。呼び名を直接書かない。
- `tests/test_terms.py` が、直書きと、用語集に無い id を止める。

## 捨てた案

| 案 | 捨てた理由 |
|---|---|
| 画面のコードに対応表を持つ | 宣言やプロファイルの文字に効かない。API と MCP が同じ呼び名にならない |
| 日本語の呼び名に統一する | 利用者 (エンジニア) がコードや会話で使う言葉と離れる |

## 結果

- プロファイルの `tiers[].invokes_next` は、コードの例 (波かっこを含む) を書く自由文なので、置き換えの対象にしない。
- 用語集の無い集計表 (古い版の build) を開いたら、画面は作り直しを促して止まる。
- 最新の状態: [../reference/marts.md](../reference/marts.md) の「画面に出す呼び名」。
