# as-built-atlas のブランド

as-built-atlas が、誰の何の役に立つものかと、名前・言葉づかい・見た目の考え方です。語彙は「判断材料 / 説明できること / 構造」を使い、評価の感嘆や道具の自慢をしません。

## コンセプト

### 一言で

> 入口から辿って、人とエージェントが同じ竣工図 (as-built) を見る。

### Value Proposition

- **誰に**: 既存システムの保守担当と、そのシステムを扱うコーディングエージェント
- **困りごと**: 「どの入口が、何を呼び、どこを読み書きしているか」を知りたいが、コードを全部読む時間は無い。LLM に要約させても、根拠が無く信用できない
- **これは**: 入口 (ジョブ・エンドポイント・画面) ごとにコーディングエージェントが分析し、根拠付きの構造化データにして、集計表 (mart) として人にも機械にも配る分析基盤
- **他と違うのは**: 自由文の wiki ではなく、形式を固定したデータ。主張ごとに「事実 / 解釈 / 不明 + 理由」と根拠 (ファイルと行) を持つ。再現できる処理は決定論で行う。MCP で機械が読める

### Positioning Statement

> as-built-atlas は、既存システムの「いまの姿」を根拠付きで知りたい保守担当とコーディングエージェントのための、入口起点のシステム分析基盤である。分析結果は形式が固定され、検証され、人と機械が同じものを見る。

### Key Messages

| メッセージ | 相手の困りごと | 裏付け |
|---|---|---|
| 入口から辿る | 全体を読む時間が無い | 入口 1 件 = 分析 1 件。入口の一覧は決定的なツールで列挙し、人が承認する |
| 根拠の無い主張を出さない | LLM の要約は信用できない | 項目ごとに 事実 / 解釈 / 不明 + 理由、根拠はファイルと行 |
| 人とエージェントが同じものを見る | ドキュメントとエージェントの知識が食い違う | 正本は 1 つ。webapp と MCP は同じ API を読む |
| 決定論でできることは決定論で | エージェントの出力は再現しない | 列挙・検証・ETL・集計はツール。エージェントは発見と解釈だけ |
| 対象に合う入口から辿る | 自分のシステムに合うか分からない | Web 画面・モバイル・API・CLI・dbt・バッチなどに分析の型があり、[プロファイルごとの見本](architecture/examples.md)で確かめられる |

### 10 秒ピッチ

> 既存システムの入口ごとに、根拠付きの竣工図をエージェントが作り、人も MCP も同じものを読む。

### 30 秒ピッチ

> 保守の現場では「この処理は何を読み書きしているか」を知るのに、コードを辿る時間が足りません。LLM に要約させても根拠が無く、信用して判断に使えません。このツールは、入口ごとにコーディングエージェントが分析し、主張ごとに根拠と「事実か解釈か不明か」を付けた構造化データにします。集計表にして webapp と MCP で配るので、保守担当もエージェントも同じ竣工図を見て判断できます。

## 名前

### 選定基準

- 何をするものか (入口 / 竣工図 / 地図) が名前から分かる
- GitHub で同名リポジトリが無い、または少ない
- 英小文字のケバブケースで、説明的

## テーマ

### 声 (voice)

- 構造的・冷静・断定を恐れない
- 「すごい」「革命」を使わない。できることとできないこと (不明 + 理由) を同じ重さで書く
- 一人称は「このツールは」。利用者を「保守担当」「エージェント」と呼ぶ

### 見た目 (visual)

色と地は、次の 2 つから決めました。

- 画面は「入口の種類」を色で見分ける必要があり、アクセント 1 色では足りない
- エディタの隣で長く見る道具なので、白地のほうが表とコードの文字が読みやすい

**考え方**: 白と黒と細い線の路線図。入口からデータまでを 1 本の路線として描く。階層は文字の大きさと余白で作り、太さと塗りでは作らない。

| 役割 | 値 |
|---|---|
| 地 | 白 `#FFFFFF` |
| 文字・強い罫 | 黒 `#0A0A0A` |
| 脇の文字 | 灰 `#6B6B6B` |
| 薄い罫 | 灰 `#E2E2E2` |
| 路線の色 (入口の種類ごとに 1 色。6 色まで) | `#0B8A5A` `#2C6FD1` `#8A4FBF` `#B26A00` `#0E8C9A` `#C2378A` |
| 書く操作・注意 | 朱 `#C7381C` |

- 彩度のある色の役割は 2 つだけ: 路線の色と、書く操作の朱。飾りには使わない
- 線は細く (罫 1px、路線 2px)。影と、背景を塗った箱を使わない
- 見出しは太くしない。大きさで分ける
- 値と部品の決まりの正本は、リポジトリ直下の `DESIGN.md` と `abatlas/webapp/css/`。この節は考え方だけを書く
- README や説明資料の図も、この考え方 (白地、黒の細い線、色は意味があるところだけ) で描く
- LP の[ロゴマーク](../site/assets/atlas-mark.png)は、頭文字の A に路線の乗換点を組み合わせる。ヘッダーとフッターでは製品名を添え、ファビコンにはマークを使う。README の見出しには製品名を使う。
- LP は技術思想の節を暗色にし、青い線で分析、緑の線で確定後の利用を示す。製品画面のキャプチャは元の配色で載せ、対象名や読み方を本文に置く。[ADR 0028](adr/0028-lp-brand.md)
- LP の冒頭では、公開見本の3D図が斜めから真上を通って一周する。画面に見えている間は無音でループし、図を押すと一時停止・再開できる。キーボードでは図にフォーカスして Enter または Space で操作する。動きを減らす設定では静止画から始まり、図を押すと回転する。[ADR 0029](adr/0029-lp-hero-loop.md)
- LP の見出し・導入文・挿絵は、スクロールが落ち着き、それぞれが画面の上から約90%まで入ると現れる。輪郭がかすかに見える不透明度6%から、少し浮かびながら本来の濃さに戻る。同時に見える場合は見出し、導入文の順に動く。分析例パネルでは見出しと説明が透明な状態から現れ、実画面の細字は元の濃さで表示する。ページ末尾では最後の文章まで届くように開始位置を調整する。技術思想の図はコードから YAML、Webapp と MCP へ経路を描く。動きを減らす設定では最初から通常の濃さで静止して表示する。[ADR 0030](adr/0030-lp-reveal-opacity.md)
