# 見本のルール

[← rules の地図へ](README.md)

対象: `examples/`。仕組みの説明は [../architecture/examples.md](../architecture/examples.md) です。

## 見本は、プロファイルごとに 1 つ

どのプロファイルにも、見本を 1 つ持ちます ([ADR 0017](../adr/0017-one-example-per-profile.md))。対象の一覧は、[../architecture/examples.md](../architecture/examples.md) にあります。

| 決まり | 理由 |
|---|---|
| プロファイルを足すときは、見本も足す | その型のシステムを分析した結果を、見られるようにする |
| 同じプロファイルに、2 つ目の見本を足さない | 直すときに、分析し直す相手が増える |
| 承認して分析した入口を、3 件以上入れる。全部の入口でなくてよい | プロファイルの書き方が分かれば足りる |
| プロファイルの版を上げたら、その見本を分析し直す | 置くのは、今の版で分析した結果だけ |

`tests/test_examples_profiles.py` が、この 4 つを確かめます。

## 見本の種類ごとの決まり

| | ことり書店 (`kotori-books`、`kotori-books-atlas`) | ほかの見本 (`umami-atlas` など) |
|---|---|---|
| 直し方 | **手で直さない。** 生成スクリプト (`examples/generator/kotori_books.py`) を直して、生成し直す | **手で直さない。** 手元の分析リポジトリで分析し直し、`examples/generator/import_atlas.py` で資産を写す |
| 題材 | 架空。実在の会社・サービス・人物を含めない。外部のホストは `.example` | 公開されているソフト。対象のコードは入れない |
| 入れるもの | 対象のコードと、分析リポジトリの資産 | 分析リポジトリの資産だけ (作業定義、入口の一覧、分析結果、レビュー)。それに、見本の `README.md`、`.env`、`.gitignore` |
| 守っているもの | `tests/test_examples.py` (再生成して差が無い) | `tests/test_examples_profiles.py` (どの見本にも当てはまる検査)。umami は、`tests/test_examples_umami.py` も |

## 守ること

| 決まり | 理由 |
|---|---|
| 形式、プロファイル、抽出器、生成スクリプトを変えたら、ことり書店を生成し直してコミットする | 見本が、今の形式に合う |
| 生成し直したら、差分が意図した範囲に収まっていることを確かめる | 例: 作業定義だけに足すつもりの項目が、全部の分析結果に写ることがある |
| 手元の絶対パスや、個人の情報を残さない。`clone_path` は `../<対象の clone の名前>` にする (写すスクリプトが置き換える) | 公開するリポジトリ |
| 見本の `README.md` に、対象、コミット、ライセンス、分析した入口、対象を隣に clone する手順を書く | 使う人が、対象を用意して、根拠の行を確かめられる。対象の権利者が分かる |
| 写す前に、作業定義の `target.commit` が、対象の公開のリポジトリにあることを確かめる (例: `gh api repos/<owner>/<repo>/commits/<commit>`) | 手元にだけあるコミットを分析した結果は、公開されていないコードの説明になる。使う人も、その版を取れない |
| 公開されていない対象の分析結果を、見本にしない。手元で試しただけの結果も入れない (試すときの置き場 `spike/` は git の管理外) | 公開できない情報を含む |
| 見本は、checkout の外へコピーして使う。checkout の中で `init` しない | `init` が git リポジトリとして初期化し、設定を書き足す |

### 資産を写すとき

```bash
uv run python examples/generator/import_atlas.py <手元の分析リポジトリ> <見本の名前> --clone-dir <対象の clone の名前>
```

- 写すのは、作業定義、入口の一覧、分析結果、レビューです。結果とレビューの置き場は、作り直します (消えた入口の結果を残さない)。
- 置き換えるのは、いちばん上の `target` の `clone_path` の値だけです。ほかの値は変えません。
- 見本の名前が置き場の外を指すとき、資産が足りないとき、手元の場所 (ホーム、分析リポジトリの場所、元の `clone_path`) が文の中に残っているときは、見本に触らずに止まります。残っていたら、分析リポジトリの側で直してから、写し直します。
- `README.md` は、スクリプトでは書きません。件数が変わったら、手で合わせます。

## 表示名

分析対象の表示名 (`target.name`) は、**作業定義だけ**に書きます。入口の一覧と、分析結果の `target` には写しません。

- 形式の上では、3 つとも同じ定義を参照するので、書けてしまいます ([schema.md](schema.md))。
- 分析結果の `target` は、「どのコミットを分析したか」の記録です。表示のための値を混ぜません。
- 生成スクリプトは、作業定義用 (`work_target`) と、入口の一覧・分析結果用 (`target_meta`) を分けて持ちます。表示のための値は、`work_target` にだけ足します。

## README の画像

- `README.md` の画像は、ことり書店の見本を、今の画面で撮ったものにします。
- 画面の見た目を変えたら、撮り直します (skill `dev-sample-regen`)。
- 撮る前に、見本を配布物の既定のプロファイルで集計し直します (試しに直したプロファイルのまま撮らない)。
