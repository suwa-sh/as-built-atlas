# 文書のルール

[← rules の地図へ](README.md)

対象: `README.md`、`docs/`、`DESIGN.md`、`PRODUCT.md`。経緯は [ADR 0035](../adr/0035-docs-by-reader-purpose.md)、[ADR 0007](../adr/0007-docs-by-topic.md)、[ADR 0001](../adr/0001-knowledge-placement.md) です。

## どこに何を書くか

置き場は、読み手の問いで選びます。

| 文書 | 読み手の問い | 書くこと |
|---|---|---|
| `README.md` | これは何か | 何であるか、何が見えるか、試し方。細かい仕組みは書かず、`docs/` を指す |
| `docs/guide/` | どうやるか | 使う人の手順。場面ごとに、人がやること、裏で動く skill とコマンド、手に入るものを分けて書く。入口 (`README.md`) は、全体の流れと、場面から文書を選ぶ表 |
| `docs/architecture/` | なぜこうなっているか | 仕組みと、その理由。入口 (`README.md`) は、全体像・地図・言葉の表。中身は、主題ごとのファイル |
| `docs/reference/` | 正確には何か | 仕様の、最新の状態。コマンド、作業定義、分析結果の形式、集計表、API と MCP、プロファイル、見本。入口 (`README.md`) は、知りたいことから文書を選ぶ表 |
| `docs/rules/` | 直すとき何を守るか | 開発で守ること |
| `docs/adr/` | なぜそう決めたか | 決定の経緯 |
| `DESIGN.md` | 画面はどう見せるか | 画面の見た目の決まり。**正本は、ここだけ** |
| `PRODUCT.md` | 誰がどの場面で使うか | 画面の利用者と、使う場面 |

手引きには、仕組みの理由と、項目の全部の一覧を書きません。理由は `docs/architecture/` を、一覧は `docs/reference/` を指します。

- 計画、進み具合の記録、検討の途中の資料は、このリポジトリに置きません。決まったことは、上の表の、読み手の問いに合う置き場 (`docs/guide/`、`docs/architecture/`、`docs/reference/`、`docs/rules/`) に、経緯は `docs/adr/` に書きます。
- 手元の場所 (絶対パス)、個人の情報、公開していない対象の名前を書きません。
- 同じ事実を、2 か所に書きません。片方を正本にして、もう片方は指します。
- `docs/guide/`、`docs/architecture/`、`docs/reference/` は、分析リポジトリにも配られます (`.abatlas/docs/` の下)。この 3 つの間は、リンクで指せます。**その外のファイル (例: `DESIGN.md`、ルートの `README.md`) へは、リンクにせず、文で指します。**
- 配る置き場を増やすときは、配布の一覧 (`abatlas/layout.py` の `OSS_REFERENCE_ITEMS`)、`Dockerfile`、リンクの検査 (`check_docs.py` の `SHIPPED`) を合わせて直します。一覧と検査のずれは、`tests/test_docs.py` が止めます。
- `docs/architecture/README.md` は、skill や設定から参照されています。場所と名前を変えません。

## 書き方

| 決まり | 内容 |
|---|---|
| 読み手は、文脈を知らない人 | 何の話かを、最初に書く |
| 一文一義。結論が先 | 「〜で、〜なので、〜だが」と続けない |
| 段落より、表・リスト・図 | 3 文を超える段落は、表かリストに分ける。1 つの段落に、事実を詰め込まない |
| 流れ・構成・関係は、図にする | mermaid で書く |
| 同じものは、同じ名前で呼ぶ | 文書は日本語の呼び名。画面の呼び名との対応は、`docs/architecture/README.md` の「言葉」の表 |
| 内部の id や、独自の用語を、説明なしに使わない | 初めて出る所で、1 行で説明する |
| 版の番号と、見積もりの時間を書かない | すぐ古くなる |
| 表の「理由」の列を省かない | 決まりだけでは、例外の判断ができない |

## 図 (mermaid)

| 決まり | 理由 |
|---|---|
| 図は、実際に描いて確かめる | 記法の誤りは、読んでも気づけない |
| 箱の文字に、かっこ・スラッシュ・波かっこ・山かっこを入れるときは、引用符で包む (`A["a (b)"]`) | `[/…/]` や `[(…)]` は、箱の形の記法として解釈される |
| 線の文字にスラッシュで始まる語を入れるときも、引用符で包む | 同上 |
| 1 枚の図に、箱は 10 個くらいまで | 多いと読めない。分ける |

## 直すとき

| 場面 | やること |
|---|---|
| 実装を変えた | 変えた事実 (コマンド、項目の名前、上限の数、ファイルの名前) を `docs/` と `README.md` で探して直す |
| 文書を動かした・分けた | ほかからの参照を探して直す: skill (`.agents/skills/`)、`AGENTS.md`、`.agents/memory/`、テスト、見本の README (`examples/*/README.md`)、コードのコメントと表示の文字 (`abatlas/`)。リンクの検査が見るのは、ルートと `docs/` の Markdown だけ |
| 画面の見た目を変えた | `DESIGN.md` を直し、`README.md` の画像を撮り直す |
| 決定を変えた | ADR を 1 つ足し、`docs/` を最新の状態に書き換える |

確かめ方 (図を描く、リンク切れを調べる、言葉の表と突き合わせる) は、skill `dev-docs` にあります。リンク切れ、配布先で切れるリンク、図の危ない書き方は、`tests/test_docs.py` も止めます (図を実際に描くところは、テストではしません)。
