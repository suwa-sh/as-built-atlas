# 対象コードの差分から、読み直す入口を選ぶ

分析リポジトリのコミットは前回の入口一覧と結果を特定します。コードの差分は対象リポジトリで取ります。入口ごとに、結果の `target.commit` から今回の作業定義のコミットまでを比較します。

## 作業一覧を出す

1. 更新前の分析資産をコミットし、その版を控えます。対象 Git の新旧の版をローカルで読めるようにします。
2. 対象を今回のコミットで checkout し、作業定義と入口一覧の `target.commit` をその版に合わせます。
3. 分析リポジトリで次を実行します。人向けの一覧に加えて、ランナー用の JSON を出せます。

```bash
docker compose run --rm abatlas impact . --from <前回の分析コミット>
docker compose run --rm abatlas impact . --from <前回の分析コミット> --json
```

ツールは今回のコミットを一時ディレクトリに展開し、入口を全件列挙します。一覧と結果は書き換えません。プロファイル・分析規約・入口の承認・リンク先・入口を包む関係も確認します。

| 作業 | 理由 | 次に行うこと |
|---|---|---|
| 承認待ち・追加分析 | 新しい候補、または承認済みで結果が無い | 列挙と承認を済ませ、分析する |
| 再分析 | 前回の定義場所や主張の根拠が変更・移動・削除された、または分析条件が変わった | ファイル差分と表示された呼び出し経路を読む |
| 廃止確認 | 前回の入口が列挙から消えた、または結果のある入口を却下した | リンク元を確かめる。人の確認後に旧資産を Git 履歴に保全し、現行の結果・レビュー・再利用記録から外す |
| 再利用候補 | 記録されている根拠と分析条件が同じ | 未記録の影響を確認して、入口ごとに確定する |

たとえば、ことり書店の共通ランナーが変わると、同じファイルを参照する32入口に共通の理由が付きます。決済処理が変わると、決済と日締めの2入口に呼び出し経路が出ます。影響一覧はファイル単位です。コードの変更内容と各入口の挙動は、分析担当者が差分を読んで判断します。

## 今回の結果を確定する

- `enumerate` で今回の一覧を保存し、入口を承認します。承認後に `impact` で一覧を作り直します。
- 共通処理の実装差分を一度読み、今回の版と根拠行を控えます。各入口では呼び出し元の設定・引数、終了条件、後続処理への伝わり方を調べます。分析結果は入口ごとの完全な YAML を保存します。
- 変更ファイルの一覧から、新しい登録規則・動的な呼び出し・追加テストが他の入口に影響しないかを確認します。影響範囲を特定できないときは、その範囲を再分析します。入口を特定できなければ全件を対象にします。
- 再利用する入口には、人が判断した理由と確認者を指定します。対象は作業定義の版と一致する clean checkout を使います。Git が無視する生成物は判定から除きます。

```bash
docker compose run --rm abatlas reuse . --from <前回の分析コミット> \
  --plan-id <impactの計画ID> --entry daily.db_snapshot \
  --by <確認者> --reason '変更のあった起動スクリプトを通らず、追加された呼び出しも無い'
```

確認記録は `analysis/reuse/` に入口ごとに残ります。判定が変わると計画 ID が変わるため、最新の一覧で確認をやり直してください。再利用を確定する操作は、入力が同じほかの候補の計画 ID を維持します。

`validate result --work` と `build` は、元結果・入口・分析条件と、対象 Git の新旧の根拠ファイルを照合します。入口の概要の `target_commit` は実際に分析した版、`effective_commit` は利用できる版です。`update_status` の `analyzed` は分析、`reused` は再利用、`stale` は旧版の結果です。進捗の `analyzed` は結果がある入口の数、`current_results` は今回有効な数、`reused_results` はそのうち再利用した数です。残りのコスト・時間は、承認済みで今回有効な結果がない入口の件数から見積もります。元の結果・分析日時・レビューを再利用で上書きすることはありません。

集計後の `diff . --from <前回の分析コミット>` は、以前と同じく入口ごとの分析内容の変化を出します。次の更新も元の分析コミットと直接比べます。各結果を保存した分析コミットの規約・入口の境界も照合します。保存時点を確認できない場合は再分析します。
