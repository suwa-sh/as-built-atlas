# 配布物を新しくする

[← 手引きの入口へ](README.md)

as-built-atlas の新しい版が出たときに、分析リポジトリを更新する手順です。

## 人がやること

| 順 | やること | コマンド |
|---|---|---|
| 1 | 版ごとの作業を確かめる。as-built-atlas のリポジトリの `CHANGELOG.md` の「更新の手順」の表で、自分が飛び越える版の行を読む | |
| 2 | 版を固定しているときは、`.env` の `ABATLAS_IMAGE` を、更新先の版のタグに書き換える (下の「版を固定したいとき」) | |
| 3 | 新しいイメージを取る | `docker compose pull` |
| 4 | 配布物のコピーと skill を置き換え、製品別の設定を作り直す | `docker compose run --rm abatlas upgrade .` |
| 5 | 1 で確かめた、版ごとの作業を行う (例: 下の「形式の項目名が変わった版のとき」、入口の列挙のやり直し) | |
| 6 | 集計し直す | `docker compose run --rm abatlas build .` |
| 7 | 画面と MCP を、新しいイメージで起動し直す | `docker compose up -d --force-recreate api` |

版ごとの作業が無いときは、3、4、6、7 の 4 つのコマンドだけで済みます。

2 を飛ばすと、3 から 7 がすべて成功しても、前の版のままになります。
`ABATLAS_IMAGE` に書いた版のイメージが、もう一度使われるためです。

5 を飛ばすと、6 の集計が止まることがあります。
集計は、入口の一覧と分析結果を検査してから始めるので、前の形式のままのファイルや、古い入口の一覧があると通りません。

## 置き換わるもの、残るもの

| もの | 例 | 更新での扱い |
|---|---|---|
| 配布物のコピー | `.abatlas/`、`compose.yaml`、`.agents/skills/` の配られた skill | 新しい内容で置き換わる |
| 製品別の設定 | `.claude/` など | エージェントの設定から作り直される |
| エージェントの設定 | `AGENTS.md`、`.agents/harness.yaml`、`.agents/memory/` | 触らない |
| 分析の資産 | `.env`、`analysis/` | 触らない |

置き換わるパスの一覧は、分析リポジトリの `.abatlas/OWNED.md` にあります。
自分用に写したプロファイル (`analysis/profiles/`) は、分析の資産なので、置き換わりません。

## 形式の項目名が変わった版のとき

新しい版で、設定や分析結果の項目名が変わることがあります。
そのときは、コマンド `migrate` で、分析リポジトリのファイルの項目名を移します。

```bash
docker compose run --rm abatlas migrate . --dry-run
docker compose run --rm abatlas migrate .
```

| 順 | やること |
|---|---|
| 1 | `--dry-run` で、書き換わるファイルを見る |
| 2 | `migrate` を実行する |
| 3 | 機械で安全に移せないと知らされたファイルを、手で直す |
| 4 | 集計し直す (上の表の 6) |

`migrate` が書き換えるのは、項目の名前です。
値は変えません。
例外は 1 つで、文の中で項目を指している「`(tier: <id>)`」という書き方は、「`(layer: <id>)`」に直します。
配布物のコピーと、分析リポジトリの外のファイルには触りません。

項目名を移した後に、続けて入口を分析し直すときは、先に、移した後の分析リポジトリをコミットします。
分析し直すときの比較の起点 (前回の分析コミット) には、このコミットを使います。
移す前のコミットは、入口の一覧が前の形式のままなので、比較の起点にできません。

## 分析し直しが要るとき

| 変わったもの | 起きること | すること |
|---|---|---|
| プロファイルの版 | 古い版で分析した結果に印が付く。版の違いだけでは、集計は止まらない | 先に、`analysis/entry-list.yaml` の `profile.version` を、新しい版に書き換える。その後で、エージェントに「分析を進めて」と頼み、印の付いた入口を分析し直す |
| プロファイルの、入口を包む関係の決まり | 入口の一覧が古いままだと、集計が止まる | 入口を列挙し直して、承認する。エージェントに「分析を進めて」と頼む |
| 分析の skill の版 (2 つ目の数字まで) | 古い版で分析した結果が、再分析の対象になる。分析し直すまで、新しい観点の集計表は、その入口について空になる | 古い版の skill で分析した入口を分析し直し、集計する。エージェントに「分析を進めて」と頼む |
| 集計表や画面だけ | 何も起きない | 集計し直すだけでよい |

分析し直した後は、もう一度集計し直して、画面と MCP を起動し直します。

## 版を固定したいとき

`.env` の `ABATLAS_IMAGE` に、版のタグを書きます。

```bash
ABATLAS_IMAGE=ghcr.io/suwa-sh/as-built-atlas:<版>
```
