# 個人情報の列を洗い出す

[← 手引きの入口へ](README.md)

分析結果に出てきたデータの列に、個人情報や認証の情報などの区分を付ける手順です。
区分を付けると、その列を読み書きする入口を、画面と MCP で調べられます。

区分は、分析結果ではなく、分析リポジトリに 1 つある**データの辞書** (`analysis/data-dictionary.yaml`) に書きます。
同じ列の区分が、入口ごとにぶれないようにするためです。

## 全体の流れ

```mermaid
flowchart LR
  S1["1 案を頼む<br>人"] --> S2["2 列を集めて案を書く<br>エージェント"]
  S2 --> S3["3 確かめて承認する<br>人"]
  S3 --> S4["4 集計し直す<br>人"]
```

エージェントが書くのは、案までです。
集計は、人が承認した行だけを使います。

## 1. 案を頼む

### 人がやること

分析結果がたまった後に、エージェントに「データの辞書を作って」と頼みます。

## 2. 列を集めて、案を書く

### 裏で動くもの

エージェントが、skill `abatlas-classify-data` に従って進めます。

| 順 | エージェントがすること | コマンド |
|---|---|---|
| 1 | 分析結果に出てきた列のうち、辞書に無いものを、案の行として足す。区分は空のまま | `dictionary` |
| 2 | 区分の無い行に、区分と、判断の根拠を書く | |
| 3 | 辞書が形式に合うことを確かめる | `dictionary --dry-run` |

エージェントは、列の名前、データの名前、分析結果の中での使われ方を材料に判断します。
名前だけでは中身が決まらない列 (例: `data`、`payload`) には、区分を書かず、その旨をメモに残します。

### 手に入るもの

- `analysis/data-dictionary.yaml` に、列ごとの行が並びます。新しく足された行は、どれも案 (`status: candidate`) です。
- エージェントの報告が出ます。足した列の数、区分ごとの案の数、区分を書かなかった列と理由が書かれます。

辞書に入るのは、分析結果が列の名前を記録した読み書きだけです。
列を「全部」とだけ記録した読み書きと、外部 API の項目は、辞書に入りません。
コマンド `dictionary` の出力は、辞書の行の数 (`fields`)、今回足した数 (`added`)、承認を待つ案の数 (`candidate`) を分けて出します。

| 出力 | 意味 | すること |
|---|---|---|
| `fields=0` | 集まった列が無い。辞書のファイルは作られない | 3 と 4 を飛ばす。列が 0 件であることは、個人情報が無いことを意味しない |
| `added=0` で `candidate` が 1 以上 | 新しい列は無いが、前に書かれた案が、承認を待っている | 3 に進み、案を確かめる |

## 3. 確かめて承認する

### 人がやること

辞書を開き、行ごとに区分を確かめます。

| 項目 | 見ること |
|---|---|
| `resource` と `field` | どのデータの、どの列か |
| `category` | 区分の案。違っていれば直す。`none` は「確かめた結果、どれにも当てはまらない」の意味 |
| `note` | エージェントが判断した根拠。迷った点 |
| `status` | 正しいと確かめた行を、`approved` に書き換える |

区分が空の行は、中身を知っている人が区分を書いてから承認します。

メモは、行の `note` に書きます。
コマンド `dictionary` が列を足すときにファイルを書き直すので、YAML のコメントは残りません。

## 4. 集計し直す

### 人がやること

```bash
docker compose run --rm abatlas build .
```

### 手に入るもの

承認した列のうち、個人情報などの区分が付いた列を読み書きする入口を調べられます。

| 使う人 | 開く所 |
|---|---|
| 人 | 画面の「分析の観点」(aspects) の、data detail のタブにある sensitive data の表 |
| エージェント | MCP で、集計表 `mart_sensitive_data` |

区分を `none` にして承認した列は、この表に出ません。
`none` の行は、確かめた記録として辞書に残ります。

## 分析結果が増えたとき

入口を足して分析した後は、もう一度「データの辞書を作って」と頼みます。
新しく出てきた列だけが、案として足されます。
承認済みの行は、変わりません。
