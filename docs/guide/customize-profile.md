# プロファイルを自分のシステムに合わせる

[← 手引きの入口へ](README.md)

配布物のプロファイルを、自分のシステムに合わせて直す手順です。
例: 使っていない層を外す、入口の拾い方を変える。

配布物のコピー (`.abatlas/`) は、配布物の更新で置き換わります。
そこを直接は直さず、分析リポジトリの中に写したものを直します。

## 全体の流れ

```mermaid
flowchart LR
  S1["1 写す"] --> S2["2 直す"]
  S2 --> S3["3 読み先を変える"]
  S3 --> S4["4 検査する"]
  S4 --> S5["5 影響する所をやり直す"]
```

## 人がやること

| 順 | やること | コマンド |
|---|---|---|
| 1 | `.abatlas/profiles/<id>/` を、`analysis/profiles/<id>/` に写す | |
| 2 | 写した `profile.yaml` を直す。分析の判断が変わる直しなら、`version` も上げる (下の「版を上げるかどうか」)。上げたときは、`analysis/entry-list.yaml` があれば、その `profile.version` も同じ値にする (初めて分析する前で、まだ無ければ、何もしない) | |
| 3 | 作業定義の `profile.dir` を、`analysis/profiles/<id>` に書き換える | |
| 4 | プロファイルを検査する | `docker compose run --rm abatlas validate profile analysis/profiles/<id>/profile.yaml` |
| 5 | 入口の一覧 (`analysis/entry-list.yaml`) がまだ無ければ、ここで [初めて分析する](first-analysis.md) の「2. 入口を見つける」へ進む。既にあれば、下の「直した内容ごとに、やり直すこと」を行う | |

検査、列挙、集計は、作業定義の `profile.dir` から、同じプロファイルを読みます。
`--profile` を自分で渡している手順があれば、写した先へ向けます。

## 直した内容ごとに、やり直すこと

入口の一覧が既にある分析リポジトリで行います。

| 直した内容 | やり直すこと | 理由 |
|---|---|---|
| 入口の拾い方 | `analysis/entry-list.yaml` の `extractors` も、新しい拾い方に書き換える。列挙をやり直し、入口の一覧を確かめて承認する | 列挙が実行するのは、一覧に書かれた抽出器とパラメータ。プロファイルの既定値は、最初に書くときの元になるだけ |
| 入口を包む関係 (`within`) | 列挙をやり直し、入口の一覧を確かめて承認する | 集計は、一覧の `within` が、いまのプロファイルの宣言と一致することを検査する。一覧が古いままだと、集計が止まる |
| `version` を上げた | 入口の一覧の `profile.version` を合わせてから (上の表の 2)、影響する入口を分析し直す | 古い版で分析した結果は、再分析の対象になる。入口の一覧の版は、列挙や承認では書き換わらない |
| どれでも | 最後に集計し直す (`build`) | 分析し直した結果が、画面と MCP に反映される |

列挙と承認、分析のやり直しは、エージェントに「分析を進めて」と頼むと進みます。

## 版を上げるかどうか

「古い版で分析した結果」の印は、プロファイルの版の比較だけで決まります。
版を据え置くと、古い決まりで分析した結果に印が付かず、そのまま残ります。

対象のコードが進んだときの更新 ([対象のコードが進んだら更新する](update-analysis.md)) では、版のほかに、プロファイルの中身と入口の拾い方の変更も調べられます。
版を据え置いていても、プロファイルを写して直した後の最初の更新では、入口の再分析が提案されることがあります。

| 直しの種類 | 例 | `version` |
|---|---|---|
| 分析の判断が変わる | 層の増減、入口の拾い方、包む関係 | 上げる |
| 表示だけが変わり、既存の結果と矛盾しない | 使っていない層を外す | そのまま |
| 入口の一覧で選んだときだけ効く決まりを足す | 選んでいない分析リポジトリの結果と矛盾しない | そのまま |

## 手に入るもの

- 自分のシステムの層と入口に合った分析結果と画面です。
- 写したプロファイルは、分析リポジトリの持ち物になります。配布物の更新では置き換わりません。配布物のプロファイルの更新は、自分で取り込みます。

## うまく進まないとき

| 起きること | 原因 | すること |
|---|---|---|
| 集計が、プロファイルを理由に止まる | `profile.dir` の場所に `profile.yaml` が無い。プロファイルの `id` が、作業定義の `profile.id` と違う。プロファイルが検査に通らない | `profile.dir` と、写したプロファイルを直す。集計は、配布物のプロファイルへ黙って切り替えない |
| 検査の出力に「プロファイルを自動で読めない」と出る | `profile.dir` の場所から読めない | `profile.dir` を直す。検査が OK でも、完了にしない |
