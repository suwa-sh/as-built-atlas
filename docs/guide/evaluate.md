# エージェントの精度を測る

[← 手引きの入口へ](README.md)

自分のコーディングエージェントが、どのくらい正しく分析できるかを測る手順です。
同梱の見本「ことり書店」の分析結果は、対象のコードと同じ仕様から生成した正解です。
手元のエージェントに同じ入口を分析させて、正解と突き合わせます。

## 用意するもの

- as-built-atlas のリポジトリの `README.md` の「10-minute quickstart」(日本語は `README.ja.md` の「10 分で試す」) を終えていること
- コーディングエージェント (Claude Code、Codex など)
- ホストの `python3`

手順は、checkout の外へコピーした `kotori-books-atlas` で行います。

## 全体の流れ

```mermaid
flowchart LR
  S1["1 正解を退避する<br>人"] --> S2["2 対象に版を作る<br>人"]
  S2 --> S3["3 入口を分析する<br>エージェント"]
  S3 --> S4["4 突き合わせる<br>人"]
```

## 人がやること

| 順 | やること | コマンド |
|---|---|---|
| 1 | 正解を退避する | `mv analysis/results analysis/truth && mkdir analysis/results` |
| 2 | 対象を git リポジトリにする | `cd ../kotori-books && git init -q && git add -A && git commit -qm sample && cd -` |
| 3 | 対象のコミットを調べる | `git -C ../kotori-books rev-parse HEAD` |
| 4 | `analysis/work-definition.yaml` と `analysis/entry-list.yaml` の `target.commit` を、3 の値に書き換える | |
| 5 | エージェントを起動し、入口を分析させる (例: 「`daily.sales.settle_orders` を分析して」) | |
| 6 | 突き合わせる | `docker compose run --rm abatlas evaluate analysis/results --truth analysis/truth` |

2 で、git の `user.name` と `user.email` が未設定のときは、`git commit -qm sample` の代わりに、次を使います。

```bash
git -c user.name=you -c user.email=you@example.com commit -qm sample
```

見本の `target.commit` は、対象の内容のハッシュです。
対象が git の履歴を持たないためで、2 から 4 で実際のコミットに置き換えます。

## 裏で動くもの

- 5 では、エージェントが skill `abatlas-analyze-entry` で分析し、別のエージェントがレビューします。
- 6 のコマンド `evaluate` は、入口の id で結果と正解を対応付け、処理の段、読み書き、パラメータを照合します。説明の文は比べません。

## 手に入るもの

全体の数字と、入口ごとの表が出ます。

| 数字 | 意味 |
|---|---|
| 適合率 | 結果のうち、正解と一致した割合。低いと、無いものを書いている |
| 再現率 | 正解のうち、結果に現れた割合。低いと、取りこぼしている |
| 状態の一致 | 一致した読み書きについて、事実、解釈、不明の区別と、不明の理由が合った数 |
| 操作だけ違う件数 | 同じデータで、操作 (読む、書く) だけが違う数 |

| 出る所 | 読める数字 |
|---|---|
| 全体 | 処理の段、読み書き、パラメータの、適合率と再現率。状態の一致。操作だけ違う件数 |
| 入口ごとの表 | 処理の段の再現率、読み書きの適合率と再現率、正解にだけある読み書き |
| `--json` を付けたときの入口ごとの値 (`per_entry`) | 上に加えて、処理の段の適合率、パラメータの適合率と再現率、状態の一致、操作だけ違う件数 |

正解にだけある入口は、未分析として数えます。
1 件だけ分析すると、全体の再現率は低く出ます。
入口ごとの表を見ます。
入口ごとの表の処理の段は、再現率だけです。
呼ばれない処理まで辿っていないか (処理の段の適合率) と、パラメータの数字を入口ごとに見たいときは、6 のコマンドに `--json` を付けます。

処理の段は、層と定義のファイルの組で照合します。
同じファイルの中の、別の関数を辿った誤りは、数字に現れません。
呼び先が正しいかは、分析結果のレビューで確かめます。

正解と違う点が 1 つでもあると、コマンドは終了コード 1 で終わります。
1 件だけ分析したときは、残りの入口が未分析なので、分析した入口が正解と一致していても終了コード 1 になります。
