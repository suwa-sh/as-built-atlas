# abatlas/webapp (分析結果の画面)

- 範囲: webapp の全ページ (入口 / 入口の詳細 / データと利用元 / 外部接続 / 共有処理 / 分析の状態 / 集計表)
- モード: Operate
- 利用者と仕事: 対象アプリを保守するエンジニア。変更前の影響調査、障害の調査、全体の把握
- 主な操作: データ・外部接続・共有部品から「触る入口」を逆引きし、入口から終点までの経路と根拠の行を確かめる
- 制約: 宣言 (`meta.abatlas`) と `/meta` だけを読む。ビルド不要の ES モジュールと CSS。外部の CDN なし。PC が主、スマホは読めればよい
- 未決: なし

## Direction contract

THESIS: 経路が主役。「入口 → 処理の段 → データ」を 1 本の路線として描き、一覧でも詳細でも同じ言葉 (線・駅・乗換駅・終点) で辿れる。拒むのは、同じ大きさのカードを並べたダッシュボードと、暗いサイドバーにクリーム地の組み合わせ。

OWN-WORLD: 白地に墨。区切りは 2px の墨の罫と 1px の薄い罫だけで、箱と影を使わない。色は路線の色 (入口の種類ごとに 1 色、宣言の順に割り当て) と、書く操作の朱。駅は太い縁の丸、乗換駅は角丸の四角、終点は塗りつぶし。操作は角丸の小さな札 (読む = 白抜き、書く = 朱の塗り)。文字は 1 書体、見出しは太さ 800、数字は等幅数字。

STORY: 利用者は、直す対象を開いた瞬間に「誰が触るか」を数と一覧で知り、1 行選ぶと経路と根拠の行まで降りられると分かる。未分析の入口の経路は「まだ引かれていない」と読める。

FIRST VIEWPORT: 左に幅 220px の白いナビ (右端に 2px の墨の罫、項目の先頭に駅の丸)。本文の上端に、種類を書いた丸・対象の名前 (40px、800)・数字 3 つを 1 行に置き、下に 2px の罫。左の列は触る入口の表 (行頭に路線の色の帯、操作の札、箇所の数)。右の列 (470px) は選んだ入口の経路で、駅が縦に並ぶ太い線。乗換駅には「ほかの入口もここを通る」と書く。経路の下に根拠の行。主な操作は表の行の選択。

SIGNATURE: 経路の線。行を選ぶと、右の路線がその入口の色で引き直される。一覧の行頭の帯と、ナビの丸も同じ路線の言葉でそろえる。動きは選択時の 180ms の切り替えだけ。

FORM: 路線図。自分の候補の 1 番目 (推しのカードを利用者が選択)。seed:5f5ad45e80207a2a

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
